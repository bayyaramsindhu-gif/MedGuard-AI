REPLIT AGENT BUILD BRIEF: MedGuard AI
1. APP OVERVIEW

App Name: MedGuard AI — Early Warning System for Patient Deterioration

One-line description: An AI-powered clinical dashboard that continuously analyzes patient vital signs to predict deterioration risk before it becomes critical, with explainable alerts that help nurses prioritize care.

Core problem it solves: Hospital staff manage many patients simultaneously and cannot continuously watch every vital sign for subtle warning trends. MedGuard AI automates that vigilance — turning raw vitals into an interpretable risk score, ranked patient priority list, and real-time alerts, so staff know exactly who needs attention and why.

Target user: Nurses, doctors, and hospital administrators on general wards or step-down units who need an early-warning layer beyond standard periodic vitals checks.

6. DATA & APIS

No external API needed — this is fully self-contained with simulated data to guarantee reliable offline demo performance.

Data Models (SQLite schema):

Patient
- id (int, PK)
- name (string)
- age (int)
- ward (string)
- admission_date (datetime)

VitalReading
- id (int, PK)
- patient_id (FK)
- timestamp (datetime)
- heart_rate (float)
- spo2 (float)
- systolic_bp (float)
- temperature (float)
- respiratory_rate (float)

RiskScore
- id (int, PK)
- patient_id (FK)
- timestamp (datetime)
- ml_risk_score (float, 0-1)
- news2_score (int, 0-20)
- risk_level (string: stable/watch/warning/critical)
- top_factors (JSON: list of {feature, impact, direction})

Alert
- id (int, PK)
- patient_id (FK)
- timestamp (datetime)
- risk_level (string)
- message (string)
- acknowledged (bool)

Synthetic Data Generator (implement exactly):

Generate 12 patients. For each patient, generate 48 hourly VitalReading records:

Baseline: HR random(60-90), SpO2 random(95-99), SBP random(110-130), Temp random(36.1-37.2), RR random(12-18)
4 of the 12 patients ("deteriorating"): starting at a random hour between 20-35, apply gradual drift over 8-12 hours: HR +0.5 to +2/hr, SpO2 -0.2 to -0.5/hr, SBP -1 to -3/hr, RR +0.3 to +1/hr
Remaining 8 patients: small random noise only, stay stable throughout
Add small realistic noise (±2-3%) to all readings regardless of trend

ML Training:

Compute NEWS2 score per reading using the standard clinical bands (RR, SpO2, SBP, HR, Temp thresholds)
Label = 1 if NEWS2 will reach ≥7 within next 4 hours, else 0
Engineer features: current values, 1hr delta, 4hr delta, 4hr rolling mean/std, trend slope, current NEWS2 score
Train XGBoost classifier on this labeled synthetic dataset, save model with joblib
Compute SHAP TreeExplainer values at inference time for explainability

Real-time simulation for demo: A backend loop advances the "simulated clock" by 1 hour every 3-5 real seconds, pushing new readings via WebSocket, recomputing risk scores and firing alerts as thresholds are crossed. Include a "Fast Forward" button to skip directly to the deterioration event for demo purposes.
